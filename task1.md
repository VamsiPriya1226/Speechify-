# General QA Questions
**Question 1:** What are the key responsibilities of a QA Engineer in the software development lifecycle?
**Answer 1:A QA Engineer is responsible for ensuring software quality by reviewing requirements,creating test cases,executing tests,reporting bugs,performing regression testing,and collabrating with developers to improve the product quality before release.

**Question 2:** What do you think is more important for QA: finding bugs or preventing bugs? Why?
**Answer 2: Preventing bugs is more important because fixing issues early saves time,cost,and effort.QA should focus on understanding requirements and improving processes to reduce defects before they occur.

**Question 3:** You find a critical bug on the day of a release. What steps would you take?
**Answer 3: If I find a bug n release day, I would immediately report it with proper details,inform stakeholders,assess the impact,help prioritize the fix, retest the issue after resolution,and recommend delaying the release if the vug affects core functionality

**Question 4:** What would you do if you found a requirement that was unclear or incomplete during testing?
**Answer 4: If requirement is unclear or incomplete, I would communicate with stakeholders, or developers to clarify the requirement before continuing testing. I would also document assumptions if needed.

**Question 5:** How would you manage testing if the development team delivers a feature at the last minute?
**Answer 5: If a feautre is delivered at the last minute,I would priortize critical functionality,perfrm RBT and Exploratory testing, focue on high impact areas and ensure essential regression tests are completed within the available time.

**Question 6:** What is exploratory testing, and when is it most useful?
**Answer 6: exploratory testing is an approach where testing is performed without pre defined test cases while simulatenously learning the application.It is most useful when requirements are unclear, time is limited, or new feautres need quick validation.

**Question 7:** What is regression testing, and how do you decide what areas to cover during regression testing?
**Answer 7:Regression testing ensures that recent code changes have not affected exisiting functionality.I decide regression coverage based on impacted modules,critical bussiness flows,frequently used feautres, and past defect-prone areas.

**Question 8:** What is a test case, and what details should a good test case include?
**Answer 8: A test case is a set of steps used to validate a specific functionality. A good test case should include test case ID, Objective,preconditons,test steps,test data,expected result, and actual result.

**Question 9:** Have you ever worked with tools for managing test documentation? Which ones, and how did you use them?
**Answer 9: Yes, I have worked with tools like JIRA, Excel and confluence for managing test documentation, trackking defects, maintaining test cases,and sharing test progress with the team. 

**Question 10:** What should be included in a QA test report?
**Answer 10: A QA test report should include testing scope,executed test cases, pass/fail status, defect summary, severity details, test coverage, risks, pending issues,and overall release recommendation.

**Question 11:** How do you handle situations where a developer disagrees with a defect you've reported?
**Answer 11: If a developer disagress with a defect, i would provide clear reproduction steps,screenshots, logs, and expected behaviour based on requirements.I would discuss professionally and involve stakeholders if clarification is needed.

**Question 12:** How do you ensure that stakeholders understand the risk of releasing software with open defects?
**Answer 12: I ensure stakeholders understand  release risks by clearly communicating open defects, their severity,bussiness imapct,affected areas, possible workarounds,and the overall risk associated with the release.

**Question 13:** How do you decide the severity and priority of a defect?
**Answer 13: Severity is decided based on how much the defect impacts functionality, while priority is determined based n business urgency and customer impact.Both help decide the order of fixing defects.

**Question 14:** You are tasked with providing a report of testing progress for a release. What would your report include?
**Answer 14: A testing progress report should include total test cases,executed cases, pass/fail percentage,defect statistics, blocked issues,testing coverage,risks, pending activities,and overall release status.

# API Testing Questions

**Question 15:** What is the difference between REST APIs and SOAP APIs?
**Answer 15: REST APIs are light weight,flexible and mainly use JSON for data exchange,while SOAP APIs are protocol-based, more secure, and mainly use XML.REST is faster and commonly used for web services,whereas SOAP is used in enterprise-level applications requiring strict security.

**Question 16:** What is the significance of HTTP methods like GET, POST, PUT, and DELETE in REST APIs?
**Answer 16: HTTP methods define the action to be performed in a REST API:
GET - retrieve data
POST - create new data
PUT - Update exisiting data
DELETE - Remove data
These methods help maintain proper communication between client and server.

**Question 17:** What tools have you used for API testing (e.g., Postman, Swagger, JMeter)? Which one do you prefer, and why?
**Answer 17:I have worked with Postman,Swagger,and basic Jmeter for API testing. I prefer postman because it is user friendly, easy to create requests, validate responses, manage collections,and automate API checks efficiently.

**Question 18:** What's your experience with manual testing?
**Answer 18: I have experience in manual testing including functional testing,Exploratory testing, UI validation, defect reporting, and test case execution for web applications and APIs.

**Question 19:** How do you test the integration of an SDK with an application?
**Answer 19: To test SDK integration with an application, I would verify installtion, configuration, API Communication,functionality,error handling, logs, Compatability,and ensure the SDK behaves correctly under differnet scenarios and edge cases.

**Question 20:** Imagine you receive a 401 Unauthorized response during testing. What steps would you take to troubleshoot?
**Answer 20: For a 401 unauthorized response, I would verify authentication credentials, access tokens,headers,API keys, token expiration, endpoint permissions, and ensure the correct authentication method is being used.

**Question 21:** What are status codes (e.g., 200, 400, 500) in an API response?
**Answer 21: Status codes indicate the result of an API request:
200 - success
201 - Resource created
400 - Bad request
401 - unauthorized
404 - not found
500 - Internal Server error
They help identify whether the request was successful or failed.
